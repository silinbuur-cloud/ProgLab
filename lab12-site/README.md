# Лабораторная работа №12. Учебный портал: вход, выход, сессия

Варианты: 7 (базовый), 8 (средний), 20 (повышенный).

Работа выполнена как интерфейсный прототип с учебной имитацией серверной части (это допускается методическими указаниями). Сайт открывается без установки: достаточно открыть `index.html` в браузере.

## Как открыть

1. Открыть файл `index.html` в Chrome, Safari или Edge.
2. Войти под тестовой учётной записью (`student1`, `student2` или `teacher1`, пароли указаны в отчёте).

Чтобы проверить выход со всех устройств, откройте сайт в двух вкладках, войдите в обеих под одним логином и нажмите «Выйти со всех устройств» в одной из них.

## Структура

```
index.html      страница входа
cabinet.html    кабинет студента (вариант 7)
teacher.html    кабинет преподавателя (вариант 8)
403.html        доступ запрещён
css/style.css   стили
js/server.js    учебная имитация сервера: пользователи, хеши паролей, сессии, маршруты API, коды 200/400/401/403/429
js/common.js    общие функции клиента: запросы к серверу, проверка доступа к странице, таймер сессии, выход
js/login.js     форма входа
js/cabinet.js   кабинет студента
js/teacher.js   кабинет преподавателя
```

## Маршруты имитируемого сервера

| Метод | Маршрут | Доступ | Ответы |
|---|---|---|---|
| POST | /api/login | все | 200, 400, 401, 429 |
| POST | /api/logout | все | 200 |
| POST | /api/logout-all | вошедший | 200, 401 |
| GET | /api/me | вошедший | 200, 401 |
| GET | /api/lessons | вошедший | 200, 401 |
| POST | /api/lessons | teacher | 201, 400, 401, 403 |
| GET | /api/students/:id/grades | свой id или teacher | 200, 401, 403, 404 |
| GET | /api/teacher/students | teacher | 200, 401, 403 |
| GET | /page/cabinet | вошедший | 200, 401 |
| GET | /page/teacher | teacher | 200, 401, 403 |

Каждый запрос записывается в консоль браузера (F12 → Console) в виде `[server] GET /api/lessons → 401`.

## Ограничения прототипа

Имитация сервера работает в браузере, поэтому не даёт настоящей защиты: данные «сервера» лежат в localStorage, идентификатор сессии (аналог cookie) — в sessionStorage. В реальном приложении эта логика переносится на сервер (Node.js + Express + express-session), а идентификатор сессии передаётся в cookie с флагами HttpOnly, Secure и SameSite.
